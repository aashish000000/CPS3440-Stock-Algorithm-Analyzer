Historical Stock Market Algorithm Analyzer

CPS 3440 group project. Three maximum-subarray algorithms and three Top-K algorithms, measured on the downloaded Kaggle S&P 500 CSV.

Home

This project asks a trading question with algorithms from an analysis course. Given daily adjusted closes, what single buy and later sell would have made the most money per share, and which records were the largest movers? We answer the first question with brute force, divide and conquer, and Kadane's scan. We answer the second with merge sort, a size-K heap, and quickselect. The command-line tool checks that the algorithms agree. The benchmark then times them at 1,000, 10,000, 100,000, and 1,000,000 records drawn from the market file.

On Apple, across 6,573 closes from 3 January 2000 through 20 February 2026, every maximum-subarray algorithm returns the same window: buy on 8 October 2002 at $0.20 and sell on 2 December 2025 at $285.92, a profit of $285.72 per share. Among 472 stocks in the downloaded Kaggle file, NVDA has the largest buy-and-hold return, 210,811.11 percent.

The write-up of pseudocode, proofs, and case-by-case bounds is in algorithms.md. The technical paper is paper.html (PDF). Slides are in the repository under presentation/.

Problem

Let the adjusted closes be P[0], P[1], …, P[n]. Define the daily change A[i] = P[i+1] − P[i]. The sum of A[start] through A[end] equals P[end+1] − P[start]. The best buy/sell window is a maximum subarray of A. If every subarray is negative, the best decision is not to trade.

Top-K takes a list of scored records and returns the K best. The order is higher score first. Equal scores break toward the earlier name, so sort and heap can be compared exactly. In the product run, a record is one stock's buy-and-hold return. In the scaling study, a record is one daily move, because the file has more than a million of those and 472 stocks.

Dataset

The measurements were run on the downloaded Kaggle S&P 500 OHLC file. The original filename is SP500_Historical_Data.csv. Columns are Ticker, Date, Open, High, Low, Close, Adj Close, and Volume. The file has 2,703,531 rows, 472 tickers, and dates from 2000-01-03 through 2026-02-20. Download steps are in data/README.md.

The benchmark file has 2,703,059 daily changes and 2,703,059 scored daily moves, from those 472 constituents, 3 January 2000 through 20 February 2026. Adjusted close is stored as an integer number of micro-dollars. The algorithms therefore compare identical integers, not rounded floats.

Prefixes of that pool are the 1K, 10K, 100K, and 1M record inputs. The same prefix is reused for every trial, so the spread across trials is measurement noise rather than a new random draw.

Solution

The program is a standard-library Python package, analyzer. prices.py loads the CSV and turns closes into changes. max_subarray.py holds the three window algorithms. top_k.py holds the sort and the heap. __main__.py is the command-line tool. benchmark.py runs the scaling study.

python3 -m analyzer data/SP500_Historical_Data.csv --ticker AAPL --k 10
python3 -m analyzer.benchmark --data data/SP500_Historical_Data.csv

A correct window is not only the largest sum. It is the earliest such window. All three window routines share that rule, and the unit tests include the CLRS example, all-negative arrays, and random arrays where the three answers must match. Sort and heap are checked the same way, including ties.

Algorithms

Brute force, Θ(n²)

prefix[0] = 0
for i in 0..n-1: prefix[i+1] = prefix[i] + A[i]
for start in 0..n-1:
    for end in start..n-1:
        consider prefix[end+1] - prefix[start]

Every window is scored exactly once. The prefix makes each score O(1), so the double loop is quadratic rather than cubic. Correctness is the claim that the best pair is the best window. Best, average, and worst time are the same because every pair is visited. Extra space is the prefix, Θ(n).

Divide and conquer, Θ(n log n)

if one element: return it when positive, else no trade
mid = (low + high) // 2
return the best of
    DIVIDE(low, mid),
    DIVIDE(mid+1, high),
    best suffix of the left half + best prefix of the right half

Any optimal window is entirely left of mid, entirely right of mid, or it crosses mid. A crossing window is a left suffix plus a right prefix, and both of those are found with a linear scan. The recurrence T(n) = 2T(n/2) + Θ(n) solves to Θ(n log n) in every case. The call stack is Θ(log n).

Kadane, Θ(n)

current = 0
for i in 0..n-1:
    if current < 0: restart at i
    current += A[i]
    keep [start, i] when it is the best positive window so far

A negative running sum is thrown away because appending it to a later element cannot help. The optimal window itself never contains a point where the sum from its start is negative, or a suffix of that window would be better. One pass is enough. Best, average, and worst time are Θ(n), and extra space is Θ(1). A linear scan is optimal: an unread element can change the answer.

Top-K by sorting, and Top-K by a heap

SORT: order by score descending, name ascending, and keep K
HEAP: min-heap of the K weakest survivors
      push until the heap is full
      replace the minimum when a better record arrives
      sort those K at the end

Sorting is correct because a total order puts the answer in the first K positions. Merge sort is Θ(n log n) in the best, average, and worst case. The heap invariant says every rejected record is worse than the current minimum. Its worst case is Θ(n log k), when every arrival enters the heap. Its best case is Θ(n + k log k), when the first K records are already the answer. Extra heap space is Θ(k). Quickselect is the third method: average Θ(n), worst Θ(n²), then a merge sort of the surviving K. The study uses k = 10.

The heap's average bound is a safe upper bound. On random scores with a fixed k, most late records lose one comparison against the root and never enter the heap, so the measured curve can sit close to linear. The worst-case input in the benchmark forces an insertion on every record.

Results

Each timed cell through 10,000 records is the median of 5 trials on the same records. Brute force at 100,000 records is one trial. The second line is the operation count: pair iterations for brute force, element reads for divide and conquer, loop iterations for Kadane, and comparisons for Top-K. Only the 1,000,000-record brute-force time is an n² projection, taken from the measured 100,000-record trial, and it is labeled projected. At 10,000 records the brute-force median was about 4537 times Kadane's median (17.67 s versus 3.893 ms). The measured 100,000-record brute-force time is 33.5 min. The projection at 1,000,000 records is 55.8 h projected.

The time per pair is not a fixed constant. On the market prefix it moved from 103 ns at 1,000 records to 353 ns at 10,000 and 402 ns at 100,000. A positive window allocates a candidate, and a longer prefix of Python integers also stops fitting in cache. The pair count is still exactly n(n+1)/2. The same function on zero-mean uniform integers took 324 ns per pair at 1,000 records and 404 ns per pair at 10,000. Zero-mean data does not remove the cost: many of those windows are still positive, and the values are large. The timings were taken on Python 3.12.3 (Intel(R) Xeon(R) Processor).

From 1,000 to 10,000 records the measured exponents were 2.54 for brute force (model 2), 1.00 for divide and conquer (model about 1.2), and 1.01 for Kadane (model 1). From 1,000 to 1,000,000 the sort exponent was 1.04 and the heap exponent was 0.86.

Comparison counts follow the case analysis more cleanly than the clock does. At one million records the best-case heap makes 1,000,009 comparisons and the worst-case heap makes 6,066,615, because every arrival is inserted. The random-order heap also makes about n comparisons, so it is the easy case in the comparison model. Its wall-clock time is nevertheless the fastest of the three at 100,000 and 1,000,000 records. The best-case and worst-case inputs are permutations produced by sorting Python objects, and scanning those pointers is less local than scanning the array in allocation order. The operation column is the one that confirms best versus worst. The clock column is the one a user would feel, and it should not be described as a pure Θ(n log k) curve on market order.

On the 472-stock product question the three window algorithms agreed, and sort, heap, and quickselect agreed. That check is separate from the scaling study: Apple has 6,573 closes (6,572 changes) in the Kaggle file, and the ranking has 472 stocks. Quickselect is in the tool, the tests, and the scaling table beside merge sort and the heap.
